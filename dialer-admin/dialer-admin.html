Coverage

Where your dialable queue actually is, against the area codes you own numbers in. A contact with no local caller ID gets dialled from an out-of-area number, which is one of the strongest "don't answer" signals there is — so the biggest gaps are the numbers worth buying first.

How many numbers you need

Reps dialing × dials per rep per day ÷ dials allowed per number per day. Sales numbers (a number assigned to one rep) are left out on both sides: that rep dials from their own number, so neither they nor their number count toward the shared pool.

Where the queue is

Only campaigns that dial from the shared pool. A campaign whose reps all dial from their own number (such as Sales) is left out — its calls never use these numbers.

Lists

Imported contacts are dialable immediately, at no cost. The calling-hours gate needs each number's own time zone, and the area code carries it — a ported US number keeps its area code and its state, so the first three digits answer the question a paid lookup used to answer for $0.0015. Import also drops undialable numbers on the digits alone, and takes mobile-versus-landline from your file's phone-type column to rank the queue.

No time zone counts the rows whose area code this build's table does not carry. It reads zero on an ordinary US list. When it does not, you have two ways out and neither needs a paid lookup for the whole list: set the campaign's fallback time zone (Campaigns → Edit) so those rows are gated on it instead of refused, or use the button on that row to resolve just those numbers for real, at $0.0015 each.

Carrier check is optional now. The one thing free cannot see is a number that is well-formed and correctly zoned but dead; a carrier check finds those before the first dial, at $0.0015 each. Skipping it costs one wasted dial per dead number — the call log retires them automatically when the carrier answers "unallocated".

Deactivate takes a list out of dialing without deleting anything: its numbers are skipped until you Reactivate it, and the date it was switched off shows beside it.

WhatsApp sender

The number WhatsApp replies go out from. It must be a number Telnyx itself owns and that is WhatsApp-enabled on the WABA — Telnyx resolves the messaging profile from the sender, so a virtual or test number can receive but never send (error 40305). WhatsApp is reply-only either way: Meta allows free text solely inside 24 hours of the contact's last message.
