Task categories

Each category sets how idle detection behaves for tasks assigned to it. Standard is normal mouse/keyboard + tab-scoped detection. Dialer-exempt (e.g. Cold Calling, Sales) holds off idle while the agent is on a recognized dialer/CRM domain, same as before. Bounded grace (e.g. Backoffice) tolerates a set number of minutes of system idle — for work like downloading a call recording, uploading it, and editing it in a desktop spreadsheet app the extension can't see — before counting as idle like anyone else.

Tasks

Dialer / CRM domains

Users on these domains (or any subdomain of them) count as tracking, not idle, even with no mouse/keyboard activity — for softphone/dialer tools where they're on a call rather than typing. Changes here take effect for users within a few minutes, with no extension update or reload needed.

Extension version

After rolling out a new build to agents, raise this to that version to force everyone still on an older one off it — a below-minimum extension is blocked from starting new sessions, and an already-running session is stopped automatically within a minute. Leave blank (or set to 0.0.0) to allow any version.

Activity scoring ceilings

The activity % shown per agent and stored on every sample is mouse/keyboard event counts scored against these per-minute ceilings (100% = at or above the ceiling). The defaults (90 mouse, 60 keyboard) are starting guesses, not measured — pull a range of real activity_samples for your team (Reports tab, or query the table directly) and set these to what real, focused work actually looks like for your agents' roles. Leave either blank to use the extension's built-in default for that channel. Takes up to 5 minutes to apply to already-running sessions (cached client-side).

Voice calling (WebRTC)

The 📞 call button in chat connects two agents' browsers directly (peer-to-peer), using free public STUN servers by default — this works for most home/office networks but can fail to connect on stricter ones (some corporate firewalls, certain mobile carriers). If calls start failing to connect for some agents, add a TURN relay server.

Using Cloudflare? Cloudflare's TURN Token ID and API Token are NOT static credentials — don't paste them into the fields below (that won't work, and would expose a secret that can mint unlimited credentials). Instead, set them as secrets on the cloudflare-turn-credentials Supabase function (supabase secrets set CF_TURN_TOKEN_ID=... CF_TURN_API_TOKEN=...) and deploy it — calls will then auto-fetch short-lived TURN credentials with no fields to fill in here.

The fields below are for a different kind of TURN server: one that gives you a real static username/password (a self-hosted coturn, or another provider that issues long-lived credentials). They're only used as a fallback if the Cloudflare function above isn't set up. Leave blank to keep using STUN only (and Cloudflare, once configured). Both people still need dashboard.html open in a browser tab to call or receive a call — there's no ringing when the app is closed.
